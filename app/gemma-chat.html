Ollama not connecting? Easiest: quit this tab and double-click Gemma Chat.command — it starts Ollama and reopens the app for you. Or in Terminal: cd path/to/hearth-ai/app bash launch-gemma.sh Leave that window open while you chat.

Opened this file directly (file://)? Then the browser sends Origin: null and Ollama replies 403 unless you allow it once: launchctl setenv OLLAMA_ORIGINS '*' pkill -f 'ollama serve' Ollama restarts on next use. Note "*" lets any website reach your local Ollama — opening the app at http://localhost:9092/ instead needs no such change.

In file:// mode, saving history to disk and Agent tools also need the helper server running (bash launch-gemma.sh); without it the app still chats and falls back to browser storage.

Choosing the model yourself, from Terminal. The launcher asks which runtime to use — 1/2 for Ollama (GGUF), 3 for MLX (LM Studio). It unloads the others first, because 24GB fits only one 27B at a time: cd path/to/hearth-ai/app bash launch-gemma.sh Or drive each runtime directly: # --- Ollama (GGUF) — appears in the OLLAMA tab --- ollama list # what is installed ollama ps # what is resident ollama run qwen3.8-27b # load + chat curl -s localhost:11434/api/generate -d '{"model":"qwen3.8-27b","keep_alive":0}' # unload # --- LM Studio (MLX) — appears in the OPENAI-COMPATIBLE tab --- export PATH="$HOME/.lmstudio/bin:$PATH" lms ls # what is installed lms ps # what is resident lms server start --cors # --cors is REQUIRED for file:// pages lms load qwen3.8-27b-mlx # load it lms unload --all # free the memory MLX models never show in the OLLAMA tab — they are a different runtime. Use the OPENAI-COMPATIBLE tab, click Use LM Studio (local MLX), and leave the API key blank.

Load fails with "insufficient system resources"? Something else is holding the memory. Check with ollama ps and lms ps, unload whichever is resident, and close heavy apps — a 27B needs ~16-18GB free.

Nothing runs unless you start it. Opening this page does not launch anything. If no model shows up, that is expected — start one from Terminal first. Ctrl+C in the launcher always unloads the model. # STOP EVERYTHING (models, both servers, page server) cd path/to/hearth-ai/app bash stop-gemma.sh # --- Ollama: start / stop --- ollama serve & # start the server ollama run qwen3.8-27b # load + chat (loads on first use) curl -s localhost:11434/api/generate -d '{"model":"qwen3.8-27b","keep_alive":0}' # unload, keep server pkill -f "ollama serve" # stop the server entirely # --- LM Studio / MLX: start / stop --- export PATH="$HOME/.lmstudio/bin:$PATH" lms server start --cors # start (--cors needed for file:// pages) lms load qwen3.8-27b-mlx # load lms unload --all # unload, keep server lms server stop # stop the server Check what is actually resident: pgrep -f "ollama serve" # nothing printed = Ollama is down ollama ps # careful: this STARTS the server if it is down lms ps Note ollama ps and ollama list will silently start the Ollama server if it is not running — use pgrep to check without starting anything.

Models stay resident for 30 minutes after last use, then release automatically (was 24h, which pinned ~18GB indefinitely).

How to use this
Quick Start
1
Start Ollama. Run ollama serve in a terminal. Pull any model: ollama pull gemma3:27b
2
Open this page. It auto-connects to localhost:11434 and detects all your installed models.
3
Pick a model & chat. Switch models anytime from the dropdown. Full streaming and markdown.
Features
Models
All Ollama models. Auto-detects every model you have installed. Switch freely mid-conversation.
Thinking
Chain-of-thought reasoning. When enabled, the model reasons step-by-step inside a collapsible block before answering. Uses <think> tag prompting. Works best with larger models.
Memory
Full chat memory. Entire conversation history is sent with each request. Use "Clear Memory" to wipe context while keeping messages visible, or delete the session entirely.
Timer
Live response timer. Shows elapsed time and estimated time remaining while generating. Final stats show tok/s and total time.
VRAM
Live GPU memory. Polls Ollama every second to show how much VRAM your loaded models are using. Color-coded: green (ok), yellow (high), red (near limit).
Artifacts
Live preview. HTML/SVG content rendered in a side panel. Use artifact code block syntax.
System
System prompt. Customize behavior per session. Saved to localStorage.
Settings
Generation params. Temperature, top-p, top-k, max tokens, repeat penalty.
📎 Attach
Files. PDFs (text extracted), PowerPoint .pptx (slide text + speaker notes), Jupyter notebooks (.ipynb with cell outputs), Python & code files, text/CSV/JSON/Markdown, images (base64 for multimodal models). Drag & drop works. Legacy binary .ppt/.doc/.xls are not supported — re-save as .pptx or export to PDF.
Memory Management
Clear Memory keeps your messages visible on screen but tells the model to forget the conversation — the next message starts fresh. Use this when context gets too long or you want a clean slate without losing your chat history. Clear All permanently deletes all sessions.
Context Window
📌 = pinned, never evicted. ✕ = dropped from context now (still visible in the chat). Rows dimmed grey are currently outside the window the model sees.
API Providers
Ollama (Local)
Already configured from boot screen. Models auto-detected.
Custom API (Anthropic-compatible)
For Anthropic, OpenRouter, or any Anthropic-compatible endpoint.
OpenAI-Compatible API
For OpenAI, Groq, Together, Fireworks, or any OpenAI-compatible endpoint.
Agent Tools
Lets the model read/list/create/edit files inside one folder you choose, and optionally run sandboxed commands. Every write, edit, or run requires your explicit approval here in the chat and is backed up (or snapshotted) first. Nothing outside the folder is reachable, and commands can't touch the network.

Permissions

Reflect Mode
